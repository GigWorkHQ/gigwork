WORKLOOM · Backend
Work marketplace: quick tasks, agent tasks, gigs, contracts. Robinhood Chain (4663),
USDG. Prepared 2026-10-16. (U) = unverified; confirm before the milestone that needs
it.
Stack:
Backend: TypeScript on Bun; Hono + tRPC; Drizzle on Postgres (+ Timescale);
BullMQ on Redis; viem; Dwellir archive RPC.
Contracts: Foundry; Solidity 0.8.x.
Accounts: ZeroDev Kernel passkey accounts (EntryPoint v0.7; ZeroDev/Alchemy
bundlers), with a second device or backup signer for recovery.
Clients: web app (main), Telegram mini app (if Telegram's rules allow it, U), mobile
shell for Local tasks.
Chain facts:
USDG: no EIP-3009 or EIP-2612, so all funding uses Permit2 with exact-amount
signatures (no standing allowances).
Keepers: no Chainlink Automation, so they're self-hosted, and every money path is
also callable by anyone.
Gas: the subsidy ended 2026-09-29, so payouts are batched and sponsored gas is
capped.

Test tasks: web apps in a sandboxed browser, or store-distributed test builds, with

Personal data in items: scanned and redacted at post. The requester attests that

Fair-pay floor:
The estimate: from Workloom-run calibration on independent Tier ≥ 1 workers.
People who fail test questions and anyone clustered with the requester are
excluded. The 65th-percentile time is used.
The floor: below $6/hour, the batch can't list.
During the run: the realised rate is tracked. A breach prompts a topUp. With no
top-up within 3 days, the unclaimed remainder is cancelled and refunded.
3. Quality engine
Test questions:
mixed in at random; show-rate capped per item; rotated per worker; never shown
to clustered workers together.
Requester-written ones are validated against agreement among high-accuracy
workers. Contested ones are retired automatically.
Accuracy: per task type. Below 80% over the last 50 test questions pauses that
type, with appeal and retraining.
Pay is never cut by test or agreement results. Test items are paid like any item.
Results feed accuracy and confidence only, for any assignment that passed format
checks.
Agreement: weighted (Dawid–Skene style). Low-confidence items get one more
assignment within budget. Answers on non-test items are correlated to catch copy
rings.
Format checks: schema and fields. Test screenshots must come from the tested
app (U: metadata check). Local photos need signed capture (U), with faces and
plates blurred.

5. GigEscrow (gigs)
interface ITaskEscrow {
    struct Batch {
        address requester; bytes32 specHash; bytes32 itemsRoot;
        uint32 assignments; uint96 payPer;
        uint96 feeReserve;        // 12% (minus verified $WLOOM discount), quote-signed
        uint96 reviewReserve;     // scales with batch size; requester-funded
        uint64 claimDeadline;
        uint64 expiresAt;         // ≥ claimDeadline + claim limit + reviewWindow + 144 h
        uint32 reviewWindow;      // ≥ 24 h, enforced
        bytes32 drawSeed;         // fixed at create; used for reviewer draws
    }
    function create(Batch calldata b, bytes calldata quoteSig) external returns (uint256 id);
    function fund(uint256 id) external;                       // exact-amount Permit2; listed only when funded
    function claim(uint256 id, bytes32 assignmentId) external;   // worker; time-boxed
    function submit(uint256 id, bytes32 assignmentId, bytes32 answerHash, bool checksPassed, bytes calldata attest) external;
        // stores submittedAt + checksPassed; locks payPer out of the refundable pool
    function approve(uint256 id, bytes32 assignmentId) external;            // requester
    function approveDefault(uint256 id, bytes32 assignmentId) external;     // anyone after reviewWindow with no rejection
    function reject(uint256 id, bytes32 assignmentId, bytes32 reasonHash) external;  // requester, within window; commits the dispute
    function draw(uint256 id, bytes32 assignmentId) external;               // anyone, ≥ k blocks after reject: blockhash(rejectBlock + k) ⊕ drawSeed → reviewer, excluding reviewers clustered with the requester
    function resolve(uint256 id, bytes32 assignmentId, bool workerWins, bytes calldata assignedReviewerSig) external;  // ≤ 72 h after draw
    function resolveDefault(uint256 id, bytes32 assignmentId) external;
        // after 72 h: checksPassed → worker credited; else one escalation (new draw); hard cap 144 h → worker credited
    function cancelUnclaimed(uint256 id) external;            // requester: closes to new claims; refunds unclaimed
    function refundUnclaimed(uint256 id) external;            // anyone after expiresAt: never-claimed/abandoned only
    function topUp(uint256 id, uint96 newPayPer, bytes calldata quoteSig) external;  // newPayPer > payPer; funds delta × (remaining + pending) atomically
}
interface IGigEscrow {
    function post(bytes32 specHash, uint96[] calldata amounts, uint64[] calldata deadlines,
                  uint32 reviewWindow, bytes calldata quoteSig) external returns (uint256 gigId); // reviewWindow ≥ 72 h
    function fundMilestone(uint256 gigId, uint8 i) external;   // amount + 8% fee + review reserve; gig lists only once milestone 0 is funded

6. PayRuns (contracts)
One paidThrough per contract, used by both run and streaming, so nothing is paid
twice.
Reserved before work: a period that isn't reserved before it starts pauses the
contract, and the worker is told before working.
Admins can never cut into reserved pay.
Pay statements are generated per run; they're not employment payslips.

9. Payments in
USDG: exact-amount Permit2 into the escrow.
x402 for agents: POST /v1/batches with payTo = TaskEscrow and a Permit2
witness = batch hash, so create + fund are atomic.
Pay from Stock Tokens (clients): one atomic user-op from the client's own
account:
1. exact-amount Permit2;
2. exact-output swap to USDG (min-out bound by the oracle, multiplier applied
once);
3. reverts if the market is closed or the oracle is stale;
4. create + fund.
Escrow holds USDG only.

13. Honest limits (engineering)
Workloom runs the attestors and the reviewer set. Reviewers are paid flat fees.
The delayed draw depends on RHC block hashes, which the sequencer
controls (U). It's better than a draw in the same transaction, not perfect.
Device attestation can be beaten by farms. Tiers, stakes and accuracy history
limit the damage.
Capture signing, blurring and the Telegram path are (U) until tested.
